1. EXECUTIVE SUMMARY

A security assessment was conducted against a locally hosted
OWASP Juice Shop application.

The assessment examined application exposure, HTTP security
headers, API behavior, authentication, input handling, and
object-level authorization.

One Broken Access Control vulnerability was confirmed during
testing: an authenticated customer account was able to retrieve
another customer's shopping basket by changing the basket ID.

A separate product-search test produced a SQLite database error
when certain special characters were submitted. This is recorded
as a potential database error disclosure issue. SQL injection
has not been confirmed.

The assessment was conducted exclusively against the local
authorized testing environment.

5. TECHNICAL FINDINGS


FINDING-001: POTENTIAL DATABASE ERROR DISCLOSURE

Affected endpoint:
GET /rest/products/search

Parameter:
q

Observation:
Normal product searches returned HTTP 200.

A single apostrophe returned HTTP 200 with an empty result.

A search containing certain combined special characters
returned HTTP 500 and exposed a SQLite syntax error.

A SQL-like literal search for "apple OR banana" returned
HTTP 200 with an empty result.

Security impact:
Database error messages may reveal implementation details
that could assist further attacks.

Severity:
Preliminary Low to Medium; requires further validation.

Status:
Potential issue - SQL injection not confirmed.

Recommendations:
- Use parameterized database queries.
- Validate and safely handle search input.
- Return generic error messages to clients.
- Keep database exception details out of HTTP responses.
- Perform additional authorized validation.


FINDING-002: CROSS-ACCOUNT BASKET ACCESS (IDOR/BOLA)

Affected endpoint:
GET /rest/basket/{basketId}

OWASP category:
A01 - Broken Access Control

CWE:
CWE-639 - Authorization Bypass Through User-Controlled Key

Observation:
Two controlled customer accounts were used.

Account 1:
Basket ID: 6
Owner ID: 27

Account 2:
Basket ID: 7
Owner ID: 28

Account 1 successfully requested Account 2's basket.

Observed response:
HTTP 200 OK
Returned basket ID: 7
Returned UserId: 28

The returned basket owner differed from Account 1's owner ID.

Security impact:
An authenticated customer may access another customer's
basket information by changing the basket identifier.

Severity:
Preliminary Medium.

Status:
Confirmed in the local OWASP Juice Shop environment.

Recommendations:
- Enforce server-side basket ownership checks.
- Compare the authenticated user's ID with the basket owner.
- Deny access to objects belonging to other customers.
- Apply object-level authorization to all customer-specific
  API endpoints.
- Add automated cross-account authorization tests.

8. HTTP SECURITY OBSERVATIONS

The target returned the following headers during inspection:

- X-Content-Type-Options: nosniff
- X-Frame-Options: SAMEORIGIN
- Access-Control-Allow-Origin: *

A Content-Security-Policy header was not observed in the
inspected response.

HSTS was not observed. The local target was accessed over
HTTP rather than HTTPS, so HSTS applicability was not
established.

The wildcard CORS configuration and missing CSP require
contextual review. They are not independently confirmed
vulnerabilities in this assessment.


9. REMEDIATION PLAN

PRIORITY 1:
Fix the cross-account basket authorization weakness.

PRIORITY 2:
Investigate and correct unsafe product-search input handling
and database error disclosure.

PRIORITY 3:
Review security-header configuration, including CSP and
CORS policy.

PRIORITY 4:
Investigate the empty authenticated profile response.

PRIORITY 5:
Introduce automated authorization tests for customer-specific
resources and regression testing for API endpoints.


10. RETESTING PLAN

After remediation, repeat the following tests:

1. Account 1 accesses its own basket.
   Expected: HTTP 200.

2. Account 2 accesses its own basket.
   Expected: HTTP 200.

3. Account 1 requests Account 2's basket.
   Expected: HTTP 403 or equivalent access denial.

4. Unauthenticated user requests a basket.
   Expected: HTTP 401.

5. Product search receives special-character input.
   Expected: Safe handling without exposing database errors.

The application has not yet been patched and the remediation
has not been independently retested.

Do not mark FINDING-002 as resolved until the retest succeeds.


11. CONCLUSION

The assessment confirmed a cross-account basket access
weakness in the local OWASP Juice Shop environment.

The product-search endpoint also exposed a database error
under certain input conditions, but SQL injection was not
confirmed.

Authentication testing was successful, and the unauthenticated
basket request was rejected.

The most important corrective action is to enforce server-side
object-level authorization for all customer-specific resources.

This report reflects the tests performed and evidence
collected to date. Additional validation and remediation
retesting are required before final sign-off.
