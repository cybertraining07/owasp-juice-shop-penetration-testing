FINDING ID: FINDING-002

TITLE: Broken Access Control - Cross-Account Basket Access (IDOR/BOLA)

APPLICATION: OWASP Juice Shop
TARGET: http://127.0.0.1:3000

AFFECTED ENDPOINT:
GET /rest/basket/{basketId}

HTTP METHOD: GET

VULNERABILITY CATEGORY:
OWASP A01 - Broken Access Control
CWE-639 - Authorization Bypass Through User-Controlled Key

TEST ACCOUNTS:
Account 1: Account1-TestUser
Account 2: Account2-TestUser

TEST RESULTS:

1. Account 1 accessed its own basket (ID 6).
   Result: HTTP 200.

2. Account 2 accessed its own basket (ID 7).
   Result: HTTP 200.

3. Account 1 requested Account 2's basket (ID 7).
   Result: HTTP 200.

4. The returned basket ID was 7.
   The returned UserId was 28.

5. Account 1's basket owner ID was 27.
   Account 2's basket owner ID was 28.

6. Account 1 successfully retrieved a basket belonging
   to Account 2.

SECURITY IMPACT:

An authenticated customer can access another customer's
basket by changing the basket identifier.

Depending on the basket contents, this may expose shopping
information, product selections, and associated basket data.

SEVERITY:
Preliminary Medium.

STATUS:
Confirmed in the local OWASP Juice Shop test environment.

RECOMMENDATIONS:

1. Enforce server-side basket ownership checks.
2. Verify that the authenticated user's ID matches the
   basket owner's UserId before returning basket data.
3. Deny unauthorized requests with HTTP 403 or an
   appropriate access-denied response.
4. Apply object-level authorization checks to all
   customer-specific API endpoints.
5. Add automated tests for cross-account access attempts.

CONCLUSION:

Cross-account basket access was successfully demonstrated.
Account 1 retrieved Account 2's basket using a valid
authentication token.

This confirms an IDOR/BOLA authorization weakness
in the local test application.
